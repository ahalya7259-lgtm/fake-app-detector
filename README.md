# Fake App Detector

A **learning project**: Python + Streamlit web app that estimates whether an Android app listing looks **genuine**, **suspicious**, or **likely fake**, using:

1. **Rule-based risk scoring** (name impersonation, dangerous permissions, rating/review mismatch, etc.)
2. A **scikit-learn model** trained on a **synthetic** dataset (generated by `data/generate_data.py`)

> **Honest limitation:** This is **not** a real malware or Play Store security product. It does not download APKs, does not use official store APIs, and is **not** accurate enough for production decisions. It is for education and portfolio practice.

---

## Features

- Streamlit form for a single app (name, developer, package, category, downloads, rating, reviews, permissions, description, age)
- Risk score (0–100) with **Genuine / Suspicious / Likely Fake**
- **Why?** section listing rule reasons (+ ML probability when the model is available)
- **Batch mode**: upload a CSV, get a results table, download CSV
- Input validation and basic error handling
- Unit tests for rules and features

## How to run

```bash
git clone https://github.com/ahalya7259-lgtm/fake-app-detector.git
cd fake-app-detector

python -m venv venv
# Windows: venv\Scripts\activate
source venv/bin/activate

pip install -r requirements.txt

# Generate synthetic training data and train the model
python data/generate_data.py
python -c "from pathlib import Path; from src.model import train_from_csv; train_from_csv(Path('data/synthetic_apps.csv'))"

# Optional: tests
pytest -q

# Launch the app
streamlit run app.py
```

Open the URL shown in the terminal (usually http://localhost:8501).

## Detection logic (summary)

| Signal | Idea |
|--------|------|
| Name impersonation | Fuzzy match (`rapidfuzz`) against popular apps; high similarity + different developer → risk |
| Dangerous permissions | e.g. tools requesting SMS or contacts |
| Rating vs reviews | Very high stars, very few reviews |
| Downloads vs age | Huge install counts on a brand-new app |
| Description spam | Phrases like “free money”, “hack”, “unlimited” |
| Package mismatch | Package tokens don’t relate to name/developer |
| ML model | Random Forest on engineered features from **synthetic** labels |

Final score ≈ **55% rules + 45% ML** (falls back to rules only if the model file is missing).

**Note:** On fully separable synthetic data the model can reach very high ROC-AUC in training. That does **not** mean real-world accuracy.

## Limitations

- Synthetic training data only — patterns may not match the real Play Store
- No APK analysis, certificates, or live store metadata
- Fuzzy matching list is small (~50 apps)
- Can produce false positives/negatives; treat labels as hints only
